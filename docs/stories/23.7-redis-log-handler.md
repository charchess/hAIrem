# Story 23.7: RedisLogHandler — Fix Recursion via Queue Worker

**Status:** Done
**Epic:** 23 - L'Observatoire

## Story
**As a** Developer,
**I want** logs from h-core to be visible in the UI without causing infinite recursion,
**So that** system activity is observable in real-time.

## Root Cause
Old implementation: `emit()` called `loop.create_task(publish_event(...))` then immediately reset `_is_emitting = False` in `finally`. The guard was already False by the time the async task ran, so any logging inside `publish_event` could re-enter `emit()` without protection.

## Fix
- `emit()` now puts to a `queue.SimpleQueue` (thread-safe, purely synchronous, no await)
- `start_worker(stop_event)` is an async coroutine that drains the queue every 100ms
- Recursion is structurally impossible: `emit()` never calls async code

## Changes
- `main.py`: `RedisLogHandler` refactored + re-enabled with `setLevel(WARNING)` + worker task
- `tests/test_23_7_redis_log_handler.py`: 7 tests (emit behavior, worker drain, error survival)
- `tests/test_logging.py`: Updated to use worker pattern
- `tests/test_polish_v2.py`: Updated `test_log_level_filtering` to use worker pattern
