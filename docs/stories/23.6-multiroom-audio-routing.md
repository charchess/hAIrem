# Story 23.6 — Multi-room Audio Routing

## Status: Done

## Goal

Router le TTS d'un agent vers le speaker HA de sa pièce, et prioriser les agents dans la pièce de l'utilisateur.

## Implementation

### `src/features/home/spatial/location/service.py`
- `get_user_room(ha_client, entity_id="person.user") -> str | None`
  - Interroge HA pour l'état de `person.user` (ou entité custom)
  - Retourne le nom de pièce si état valide (non `not_home`/`unknown`)
  - Retourne `None` si HA indisponible ou erreur

### `src/services/audio/tts_orchestrator.py`
- `__init__` accepte `room_router: MultiRoomAudioRouter | None = None`
- `synthesize_and_broadcast(text, agent_id, voice_id, room_id=None)`
  - Redis broadcast inchangé (toujours publié)
  - Si `room_router` et `room_id` → appel `room_router.route(url, room_id, agent_id)`
  - Erreur de routing non-bloquante

### `src/main.py` — `HaremOrchestrator`
- `self.user_room: str | None = None` dans `__init__`
- `world_context` enrichi avec `"location": getattr(self, "user_room", None)` dans les deux calls arbiter (broadcast + inter-agent)
- Le bonus `location_bonus = 0.1` existant dans l'arbiter s'active automatiquement pour les agents dans la pièce de l'utilisateur

## Tests TDD (RED → GREEN)

- `tests/test_23_6_multiroom.py` — 11 tests

**LocationService :**
- `get_user_room()` retourne la pièce HA
- Retourne `None` si `not_home`, HA indisponible ou exception
- Accepte `entity_id` custom

**TtsOrchestrator :**
- `synthesize_and_broadcast` route vers HA avec `room_id`
- Pas de routing si `room_id=None` ou `room_router=None`
- Redis broadcast toujours envoyé même avec routing actif

**Orchestrateur :**
- `user_room` présent → passé dans `world_context["location"]`
- Absent → `world_context["location"] = None` (pas de crash)
