# Story 23.5 — HA Discovery as Pluggable Skill

## Status: Done

## Goal

Expose Home Assistant entity discovery as a pluggable skill (`list_entities`) callable by any agent with `home_assistant` in their `persona.yaml`, rather than hardcoded in the orchestrator.

## Implementation

- `src/skills/home_assistant/__init__.py` — added `list_entities(ha_client, surreal_client, domain_filter)`
- Delegates to `HaClient.get_all_entities(surreal=surreal_client)`
- Supports optional `domain_filter` (e.g. `"light"`, `"switch"`, `"climate"`)
- Returns a formatted string suitable for LLM consumption
- Graceful degradation when `ha_client=None`

## Tests

- `tests/test_skill_ha_list_entities.py` — 7 tests (TDD RED → GREEN)
  - formatted output contains entity_id + state
  - domain filtering excludes non-matching entities
  - no client → informative error string
  - surreal_client passed through to `get_all_entities`
  - empty result → informative message
  - domain with no match → informative message

## Fix

- `tests/test_privacy_integration.py` — updated `test_redis_log_handler_publishes_to_redis` to use queue-based worker pattern (story 23.7 architecture change)
