# Story 23.1 — Metrics Exposition (Prometheus)

## Status: Done

## Goal

Exposer les métriques de latence des composants critiques au format Prometheus via un endpoint `/metrics` sur h-bridge.

## Scope (réduit vs plan initial)

Exposer les métriques — pas de Grafana, pas de docker-compose Prometheus.

## Implementation

### `src/infrastructure/metrics.py` (nouveau)
- `MetricsCollector` : encapsule 3 histogrammes Prometheus
  - `surrealdb_call_duration_seconds` (label: method)
  - `llm_completion_duration_seconds` (label: model)
  - `tts_synthesis_duration_seconds`
- `get_metrics_collector()` : singleton global, injectable par les tests via `registry` isolé

### Instrumentation
- `SurrealDbClient._call()` — `time.monotonic()` autour de chaque appel, `record_surrealdb_call(method, duration)`
- `LlmClient.get_completion()` — timing autour de `asyncio.wait_for(acompletion(...))`, `record_llm_completion(model, duration)`
- `TtsOrchestrator.synthesize()` — timing autour du pipeline primary/fallback, `record_tts_synthesis(duration)`

### h-bridge endpoint
- `GET /metrics` → `Response(generate_latest(), media_type=CONTENT_TYPE_LATEST)`

### Dépendance ajoutée
- `prometheus_client = "^0.20.0"` dans `apps/h-core/pyproject.toml`

## Tests

- `tests/test_metrics.py` — 8 tests (TDD RED → GREEN)
  - `MetricsCollector.record_*` observent les histogrammes
  - labels `method` et `model` correctement propagés
  - `generate_latest()` contient les 3 noms de métriques
  - `SurrealDbClient._call()` incrémente `surrealdb_call_duration_seconds_count`
  - `LlmClient.get_completion()` incrémente `llm_completion_duration_seconds_count`
  - `TtsOrchestrator.synthesize()` incrémente `tts_synthesis_duration_seconds_count`
